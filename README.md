# MB CHAT — настройка

Файлы: `index.html`, `app.js`, `config.js`, `supabase.sql`. Сборка не нужна.

## 1. Supabase
1. Зайдите на supabase.com → **New project** (бесплатного тарифа достаточно).
2. **SQL Editor → New query** → вставьте весь `supabase.sql` → **Run**. Это создаёт таблицы, генерацию ID вида `MB482915`, RLS-политики, Realtime и хранилище аватаров.
3. **Authentication → Providers → Email**: для первого теста выключите **Confirm email**, иначе нужно подтверждать почту.
4. **Project Settings → API**: скопируйте **Project URL** и ключ **anon public**.
5. Откройте `config.js` и вставьте их. Ключ `service_role` не используйте и не публикуйте — anon-ключ безопасен в браузере, потому что данные защищает RLS.

## 2. GitHub Pages
1. Создайте публичный репозиторий, загрузите 4 файла в корень (на iPhone: приложение GitHub или сайт github.com → Add file → Upload files).
2. **Settings → Pages → Deploy from a branch → main / (root) → Save**.
3. Через 1–2 минуты сайт будет по адресу `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПО/`.
4. В Supabase: **Authentication → URL Configuration → Site URL** — вставьте этот адрес.

## 3. Проверка двух аккаунтов
1. Chrome: откройте сайт → Регистрация → в «Профиле» увидите свой ID.
2. Safari: откройте тот же адрес → зарегистрируйте второй аккаунт.
3. В Safari: «Поиск» → введите ID первого → «Найти» → «Написать» → отправьте сообщение.
4. В Chrome оно должно появиться без перезагрузки (уведомление сверху, счётчик на «Чаты»). Ответьте — оно придёт в Safari.
5. Галочки: ✓ отправлено, ✓✓ доставлено, голубые ✓✓ прочитано.

## Если не работает
- «Профиль не найден» — `supabase.sql` выполнен не полностью; пересоздайте проект и выполните целиком.
- Сообщения не приходят сразу — проверьте, что выполнена строка `alter publication supabase_realtime add table public.messages`.
- Белый экран — проверьте `config.js` (URL и ключ без лишних пробелов).
